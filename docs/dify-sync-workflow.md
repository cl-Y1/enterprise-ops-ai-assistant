# Dify 知识库更新衔接流程

> 适用于企业智能运维知识助手 V1.3 文档版本管理模块。<br>
> 目标：让“本地文档变更”与“Dify 知识库生效”之间有清晰、可追溯、可回滚的交接，而不是直接覆盖生产知识库。

## 1. 设计原则

1. **本地先留痕，再更新 Dify**：每个版本先有更新原因、更新人和内容快照。
2. **审核与发布分离**：审核通过只代表内容可发布，不代表已同步到 Dify。
3. **Dify 更新需要人工确认**：知识库替换会触发重新分段和索引，必须确认索引完成后再发布。
4. **历史不可丢失**：新版本发布后，旧发布版本自动归档，内容仍可下载。
5. **默认不自动写入知识库**：V1.3 使用人工交接，避免误覆盖生产知识库；自动同步作为后续扩展。

## 2. 角色

| 角色 | 职责 |
| --- | --- |
| 文档更新人 | 创建版本、填写更新原因与内容 |
| 审核人 | 审核内容准确性、完整性和时效性 |
| 发布人 | 在 Dify 完成更新并确认索引后，登记同步并发布 |
| 知识库负责人 | 抽查 RAG 问答效果，决定是否回滚 |

当前 V1.3 使用单一管理员账号，三个角色可以由同一人完成；正式生产建议拆分权限和账号。

## 3. 状态模型

### 审核状态

```text
draft（草稿） → pending（待审核） → approved（审核通过）
                       ↘ rejected（已驳回） → 修改后重新提交
```

### 发布状态

```text
unpublished（未发布） → published（已发布）
                              ↓ 新版本发布
                         archived（已归档）
```

### Dify 同步状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 已关联 Dify，等待人工完成知识库更新 |
| `synced` | 已在 Dify 完成更新并登记同步说明 |
| `not_required` | 文档未关联 Dify，发布只更新本地记录 |

## 4. 标准操作流程

```text
┌──────────────┐
│ 1. 新增版本   │  更新原因 + 更新人 + 文档内容
└──────┬───────┘
       ▼
┌──────────────┐
│ 2. 提交审核   │  draft / rejected → pending
└──────┬───────┘
       ▼
┌──────────────┐
│ 3. 审核       │  approved / rejected
└──────┬───────┘
       │ approved
       ▼
┌──────────────────────┐
│ 4. 下载 / 复制 Markdown │
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 5. 在 Dify 替换文档     │  等待索引 completed
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 6. 登记 Dify 同步说明   │  pending → synced
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 7. 发布版本             │  published
└──────┬───────────────┘
       ▼
┌──────────────────────┐
│ 8. 旧版本自动归档       │  archived
└──────────────────────┘
```

### 步骤 1：新增版本

进入 `/admin/documents`，打开文档，点击「新增版本」。

必须填写：

- 更新原因，例如「补充 Service 日志检查步骤」；
- 文档内容（Markdown/纯文本）；
- 更新人自动记录为当前管理员。

新版本默认为草稿，不会立即影响 Dify。

### 步骤 2：提交审核

在版本详情页点击「提交审核」，状态变为「待审核」。

### 步骤 3：审核

审核人可以：

- **通过**：状态变为「审核通过」；
- **驳回**：必须填写审核意见，状态变为「已驳回」。修改后可以重新提交。

### 步骤 4：下载或复制内容

审核通过后，在版本内容区点击「下载 .md」或「复制内容」。

建议保留下载文件或复制内容作为本次 Dify 更新的操作依据。

### 步骤 5：在 Dify 更新知识库

在 Dify 控制台完成：

1. 打开对应知识库；
2. 按文档 ID 找到关联文档（与后台填写的 `dify_document_id` 一致）；
3. 替换文档内容；
4. 保存并等待重新分段、索引完成；
5. 确认文档索引状态为可用/完成，而不是解析中或失败。

> 如果更新后索引失败，**不要**在本地点击发布。先修复 Dify 索引问题，或回退 Dify 文档。

### 步骤 6：登记 Dify 同步

回到本地版本详情页，在「Dify 知识库同步」卡片填写同步说明，例如：

```text
2026-11-06 17:00 在 Dify 替换文档，索引状态 completed；操作人：admin
```

点击「确认已同步」。系统记录：

- 同步状态 `synced`；
- 同步说明；
- 登记人；
- 登记时间。

### 步骤 7：发布版本

点击「发布此版本」。系统会：

- 将当前版本设为 `published`；
- 把之前的发布版本设为 `archived`；
- 更新文档的当前发布版本；
- 写入操作记录。

### 步骤 8：验证 RAG 回答

在聊天页面使用真实业务问题验证：

- 新内容是否能被检索到；
- 回答是否引用了正确文档；
- 旧内容是否仍被错误引用；
- 多轮追问是否正常。

建议至少验证一个标准问题和一个边界问题。

## 5. 字段映射

| 本地字段 | Dify 对应 |
| --- | --- |
| `documents.dify_dataset_id` | 知识库 ID，Dify URL 中 `/datasets/` 后的 ID |
| `documents.dify_document_id` | 知识库中的文档 ID |
| `document_versions.content` | 更新到 Dify 的文本内容 |
| `document_versions.update_reason` | 本地审计字段，不自动写入 Dify |
| `document_versions.updated_by` | 本地审计字段 |
| `document_versions.dify_sync_note` | 本次 Dify 操作说明 |
| `document_versions.publish_status` | 本地发布状态，不自动改变 Dify 应用 |

## 6. 失败与回滚

### Dify 更新失败

- 本地版本保持「审核通过」和「待同步」；
- 不点击发布；
- 修复 Dify 文档或索引问题后重新操作；
- 如果是错误内容，重新编辑一个新版本，不要修改已归档版本。

### 已发布版本内容错误

1. 找到上一个已归档版本；
2. 下载旧版本内容；
3. 新建版本，更新原因写「回滚到 vX」；
4. 重新审核、同步 Dify、发布；
5. 旧错误版本自动归档。

> 归档版本不可直接重新发布，确保历史链路清晰。

## 7. 与 Dify 官方 API 的关系

Dify 官方提供“用文本更新文档”接口：

```text
POST /datasets/{dataset_id}/documents/{document_id}/update-by-text
Authorization: Bearer {KNOWLEDGE_API_KEY}
```

请求体至少包含 `name` 和 `text`，更新文本后会触发重新索引；知识库接口需要用**知识库 API Key**，不是聊天应用的 App API Key。

官方文档：[Update Document by Text](https://docs.dify.ai/en/api-reference/documents/update-document-by-text)

V1.3 暂不自动调用该接口，原因：

- 需要单独配置知识库 API Key，权限比聊天 Key 更大；
- 索引是异步过程，需要轮询状态；
- 误覆盖生产知识库的代价高；
- 先通过人工确认建立流程和审计，再逐步自动化更稳妥。

未来可扩展为：

1. 管理员配置 `DIFY_KB_API_KEY`（仅后端）；
2. 发布前点击「同步到 Dify」；
3. 后端调用 `update-by-text`；
4. 轮询索引状态；
5. 成功后自动记录 `synced`；
6. 失败时保留待同步，不发布本地版本。

## 8. 操作检查清单

- [ ] 版本有明确的更新原因和更新人
- [ ] 审核通过
- [ ] 已下载或复制正确版本内容
- [ ] Dify 中对应文档 ID 正确
- [ ] Dify 索引已完成
- [ ] 已填写同步说明
- [ ] 本地发布成功
- [ ] 旧版本已归档
- [ ] 聊天页面已验证新内容可检索
- [ ] 出现异常时有回滚版本方案
